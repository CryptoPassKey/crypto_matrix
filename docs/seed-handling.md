# シードの扱い（機能別仕様）

シード（カード配列シード番号欄への入力文字列）は、機能ごとに解釈が異なる。
これは意図的な仕様であり、機能横断で共通の正規化に統一してはならない。

| 機能 | シードの扱い |
| --- | --- |
| 盤面生成・Backup の鍵 | 数値解釈に正規化したシード（`CMSeedKey.canonicalSeedKey`）。数値シードは `String(parseSeedValue(...))`、それ以外は trim 済みの文字列そのもの |
| Backup の原文保存 | 上記とは別に、入力文字列そのものを保持する（下記） |
| TimeLock | 原文文字列を厳密に使用（trim のみ） |
| TimeSecret | 原文文字列を厳密に使用（trim のみ） |
| Seed Vault | 入力文字列をそのまま暗号化して保存。鍵導出は既存仕様を維持 |

## Backup の原文保存

BIP39 系バックアップのコアは、シードを32bit数値として格納する。このため
数値シードのうち、コアから復元される文字列 `String(parseSeedValue(t) >>> 0)` が
入力文字列 `t` と一致しないもの（先頭ゼロ・符号・32bit超）は、コアだけでは
原文を再現できない。

`CMSeedKey.seedNeedsTextBackup(seedText)` が真になるシードについては、既存の
シード文字列ブロック（コア内の `seedTextFollows` フラグ＋追加ブロック）を
使って原文を保持する。

- 設定フレーズ: 原文保持が必要な場合は48単語、不要な数値シードは従来どおり24単語。
- 拡張・暗号化・秘密分散の各バックアップ: 本体バージョン3でシードブロックを同梱する。
- 英数字シード（v2）は従来どおり常に対象。版6に格納できる場合は版6コアに文字列を格納する。
- 原文がシードブロックの容量（23バイト）を超える数値シードは、従来形式
  （コアのみ）を維持し、原文は保持しない。

復元時は、原文が保存されていれば入力欄に原文文字列を戻す。盤面生成と Backup の
鍵は従来どおり数値解釈に基づくため、例えば "007" と "7" は同じ盤面・同じ
Backup 鍵のまま、復元後の入力表記だけが "007" に戻る。

## 旧バージョンのバックアップについて

本対応以前に作成されたバックアップには原文情報が含まれていない。旧形式の
数値シードのバックアップは従来どおり復元できるが、入力時に先頭ゼロ等があった
場合でも、その原文は保存されていないため回復できない（復元結果は数値表記になる）。
破損として扱うことはしない。
